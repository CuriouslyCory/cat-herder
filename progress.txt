## Codebase Patterns
- Entity tools in MapEditor use a separate `_selectedEntityTool: EntityTool | null` field — selecting one clears the other (terrain ↔ entity mutual exclusion via `selectTool`/`selectEntityTool`)
- Entity markers use `geometry: "sphere"` (vs terrain blocks which use `geometry: "box"`) — gives immediate visual distinction between entity markers and terrain tiles
- `RESOURCE_RESPAWN_DEFAULTS` is exported so tests can assert against it directly without magic numbers
- Hidden terrain zones reuse the same mousedown/mouseup drag pattern as water zones — just a separate set of state vars (`_hiddenDragStart`, `_hiddenDragGhost`) feeding `createHiddenTerrainZone()`
- Player spawn uniqueness: `_placePlayerSpawn()` removes the old handle via `sceneManager.removeMesh()` before assigning the new one — tests verify `removeMesh` is called with the prior handle
- Entity config section (`_entityConfigSection`) is cleared via `textContent = ""` and rebuilt by `_updateEntityConfigSection()` on each `selectEntityTool()` call — avoids stale DOM refs

## 2026-05-08 - US-303
- MapEditor is dev-gated via `process.env.NODE_ENV === 'production'` guard in constructor — same pattern as DebugMenu
- DOM overlays (banner, panel) append to `container.parentElement ?? document.body`; container is the canvas element
- SceneManager is abstracted behind a local `SceneManagerLike` interface in MapEditor.ts to avoid importing Three.js types and keep tests clean
- Test DOM mocks: use a `createdElements[]` queue (each `createElement` call returns a fresh MockEl) so banner (index 0) and panel (index 1) are independently testable
- For tests that need SceneManager, always use a SEPARATE container mock so event listener calls don't bleed between test setups
- `as any` is acceptable for internal interface mocks in tests (no eslint suppression needed — rule not configured for this pattern)
- Block meshes use unit cubes (dims: [1,1,1]) with scale.y = height — avoids geometry recreation on height changes; updateTransform(handle, {y: h/2}, rot, {y: h}) is all that's needed
- `SceneManagerLike` in MapEditor.ts must stay in sync with the real SceneManager API (setMeshEmissive, setMeshColor, etc.) — extend both together
- Water zone drag uses mousedown/mouseup pair; a `_suppressNextClick` flag prevents the `click` handler from double-firing after a drag completes
