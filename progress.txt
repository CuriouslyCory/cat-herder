## Codebase Patterns
- US-304 added `EditorToolMode = 'move' | 'delete'` as a third, mutually exclusive tool selection alongside terrain/entity tools — setting any one clears the others
- Move tool drags the *real* object (no ghost) — updates `obj.x/z` and `updateTransform` in real-time on mousemove; mouseup sets `_suppressNextClick` to prevent the click handler from also firing
- `_findPointObjectAt(gx, gz)` returns a discriminated `MovingObject` union that `_removeFoundObject` and `_updateObjectPosition` can switch on; zone objects (water, hidden terrain) are excluded as they're not point-clickable
- Keyboard shortcuts M/D/1-9 call `e.stopPropagation()` while editor is active to prevent game InputManager from seeing them
- `excludeHandles` set in mousemove now includes both `_ghostHandle` and the moving object's handle so screenToWorld hits ground geometry during drag
- Entity tools in MapEditor use a separate `_selectedEntityTool: EntityTool | null` field — selecting one clears the other (terrain ↔ entity mutual exclusion via `selectTool`/`selectEntityTool`)
- Entity markers use `geometry: "sphere"` (vs terrain blocks which use `geometry: "box"`) — gives immediate visual distinction between entity markers and terrain tiles
- `RESOURCE_RESPAWN_DEFAULTS` is exported so tests can assert against it directly without magic numbers
- Hidden terrain zones reuse the same mousedown/mouseup drag pattern as water zones — just a separate set of state vars (`_hiddenDragStart`, `_hiddenDragGhost`) feeding `createHiddenTerrainZone()`
- Player spawn uniqueness: `_placePlayerSpawn()` removes the old handle via `sceneManager.removeMesh()` before assigning the new one — tests verify `removeMesh` is called with the prior handle
- Entity config section (`_entityConfigSection`) is cleared via `textContent = ""` and rebuilt by `_updateEntityConfigSection()` on each `selectEntityTool()` call — avoids stale DOM refs
