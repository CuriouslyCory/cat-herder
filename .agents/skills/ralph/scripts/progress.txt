## Codebase Patterns
- CatAISystem runs FIRST in the fixed-step loop and drives Idle→Active→Expired state transitions for all cats from CAT_REGISTRY data; per-cat systems (ZoomiesSystem, CuriositySystem, PounceSystem) react to states but never set them
- CuriositySystem detects "first Active tick" via `reveal.revealedEntities.length === 0` (not via Idle state); CatAISystem transitions Idle→Active in the same frame so CuriositySystem sees Active and empty list simultaneously
- ZoomiesTrail overlap is a manual oriented-AABB check (not PhysicsEngine trigger) — project player offset onto trail axis (along) and perpendicular (perp), compare to halfLength/halfWidth
- SpeedBoost component is added/removed by ZoomiesSystem each fixed tick; MovementSystem reads it to scale walkSpeed before computing targetX/Z
- Movement cat trail entity has no PhysicsEngine body — only Transform + Renderable + ZoomiesTrail; position/rotation synced by RenderSystem normally
- CatCompanionManager.trailEntities Map<catEntity, trailEntity>: created in summon() for effectType='movement', destroyed in dismiss() before destroyEntity(catEntity)
- ZoomiesSystem must be instantiated after CatCompanionManager (dependency); runs at end of fixed-step sub-tick (after OxygenSystem)
- PhysicsEngine has a flat-floor fallback (y < body.config.size clamps to size) so the player stays on y=0 terrain without registering every tile as a physics body
- Terrain/launch cats register PhysicsEngine static bodies (isStatic=true, layer=1, mask=1) so the player's downward raycast detects their top surface; dismiss() removes the body
- getCatHalfHeight(def) / getXZHalfExtent(def) helpers in CatCompanionManager derive correct extents from MeshConfig geometry kind + behavior.params without per-cat switch logic
- Cat entity center Y = surfaceY + halfHeight (so mesh bottom rests on terrain, not half-underground); PhysicsEngine body position matches
- Only the player has a PhysicsEngine body by default; terrain tiles (flat floor) rely on the y≥0 clamp; elevated terrain needs registered physics bodies (added for cats in US-106)
- Cat definitions live in src/game/cats/definitions/<CatType>.ts; all exported via CAT_REGISTRY Map<CatType,CatDefinition> in definitions/index.ts — systems should import CAT_REGISTRY, not individual files
- GatheringSystem uses distance check (distSq < INTERACT_RANGE_SQ) not trigger events to detect nearby resource nodes; nodes have collisionMask=0 (no physics response needed)
- Resource node entities are created in Game.spawnTestMapResourceNodes() after loadMap(); not part of MapData/MapManager (world entities, not terrain)
- GameState.hasInventorySpace() / addResource() provide the basic inventory contract; capacity enforcement happens in US-112 but the interface is forward-compatible
- HUD gather progress bar lives at bottom:110px (above cat bar at bottom:56px) and uses display:none to hide when not gathering — same pattern as oxygen gauge
- CatDefinition.behavior.params is Record<string, number|string|boolean> for cat-specific config (no per-cat union types needed in the interface)
- OxygenState is added/removed by WaterSystem alongside SwimmingState — both live and die together on water entry/exit
- OxygenSystem queries OxygenState+SwimmingState+PlayerControlled; OxygenState is always paired with SwimmingState (no need for null guards when both appear in query)
- SceneManager.addMesh() now supports opacity field; setMeshColor/setMeshOpacity allow runtime material mutation without recreating meshes
- CatPlacementSystem runs in the variable-rate render pass (not fixed-step loop) so clicks are processed exactly once per render frame
- GameState is instantiated in Game.ts before CatCompanionManager (dependency order); CatCompanionManager gets a `() => playerEntity` getter to avoid circular refs
- UIManager.setCatCatalog() must be called after map load (catalog comes from CatCompanionManager.getCatalog() which reads CAT_REGISTRY)
- HUD.setCatalog() builds cat slot DOM elements lazily — call it once at init, then update via setCatBar() each frame
- HUD.update(dt, oxygenPercent, health, maxHealth) — UIManager.update(dt, HUDState?) is the call site; Game.buildHUDState() assembles the snapshot each render frame
- Player health lives in PlayerControlled.health/maxHealth (integer hp); OxygenState.healthDrainAccum accumulates sub-frame losses to avoid float rounding
- CSS keyframe for oxygen warning pulse is injected once via <style id="__oxygen-pulse-style"> to avoid duplicates
- Water triggers use collisionLayer=1/mask=1 (player layer) so CollisionSystem fires trigger events; floor tiles use layer=2/mask=0 (PhysicsEngine raycasts only)
- SwimmingState lifecycle is event-driven (trigger:enter/exit from CollisionSystem); MovementSystem applies swim physics by querying for SwimmingState each frame — no state machine
- PhysicsEngine.setGravityEnabled(handle, bool) controls per-body gravity; must be called when adding/removing SwimmingState
- Terrain entities are created before the player, so terrain entity IDs are always smaller; in pairKey(a,b) the smaller id comes first → water entity is usually "trigger" in events
- Game loop order: movementSystem → physics.step() → collisionSystem → waterSystem (WaterSystem reacts to trigger events emitted by CollisionSystem)
- Config changes: swimSpeed/swimSpeedVertical replaced with swimSpeedSurface(3.2), swimSpeedDive(2.0), swimSpeedAscend(2.5), swimSpeedVertical(1.5), swimAcceleration(0.5)
- DebugMenu pattern: gated by `process.env.NODE_ENV !== "production"` at construction, returns early leaving all element refs null. DOM panel built via imperative createElement, appended to canvas parent. Ctrl+D toggles. Game.ts stores as `debugMenu: DebugMenu | null` and calls debugMenu?.update(realDt) each frame + debugMenu?.dispose() in destroy().
- Persistence: auto-save interval + beforeunload beacon. Persistence.forceSave()/load()/deleteSave() for debug. SaveData versioned with migrations in src/game/state/migrations.ts.
- MapData interface: { name, size:{width,depth}, terrain:TerrainCell[][], cellSize, spawnPoints:SpawnPoint[] }. MapManager.loadMap() builds entities from terrain grid via greedy-rectangle merge.
- CameraController supports CameraMode = "follow" | "free"; free mode allows panBy(dx,dz) and setFocus(x,y,z). Follow mode tracks targetEntity.
