## Goal & acceptance criteria

Introduce a single **save-codec** module (`src/game/state/SaveCodec.ts`) that OWNS the save-data
shape. Today, adding one saved field means editing four places that must stay in lockstep:

1. `GameState.serialize()` / `GameState.restore()` — internal `{ player, world }` shape
   (`src/game/engine/GameState.ts:55-58`, `:133-160`).
2. The hand-written converters `toExternalSaveData()` / `fromExternalSaveData()`
   (`src/game/state/Persistence.ts:14-53`).
3. The Zod `saveDataSchema` (`src/game/state/SaveData.ts:9-44`).
4. The non-position dirty-path list `NON_POSITION_PATHS`
   (`src/game/state/Persistence.ts:60-73`).

Miss one and you silently get a field that saves but never restores, or never marks the save
dirty. The codec collapses (2), (3), and the derivation of (4) into ONE declaration list.

**Acceptance criteria** (from the issue, made concrete):

- [ ] The saved-field list lives in exactly one module (`SaveCodec.ts`). The external↔internal
      converters, the Zod schema, and the non-position dirty-path list are all *derived* from it,
      not hand-maintained in parallel.
- [ ] A round-trip test proves `decode(encode(state))` deep-equals the original internal state,
      and would fail if a field were declared on only one side.
- [ ] **CRITICAL — byte-compatibility:** the external save-data shape is unchanged. Existing saves
      in the DB load without migration. `JSON.stringify` of an emitted save is byte-identical
      before vs after this change (same keys, same nesting, same key *insertion order*).
- [ ] Position-throttled vs non-position dirty tracking behaves exactly as before (the five
      throttle tests in `Persistence.test.ts:240-278` pass unchanged).
- [ ] The migrations module (`src/game/state/migrations.ts`) continues to run on load, unchanged.
- [ ] `pnpm build`, `pnpm lint`, `pnpm typecheck`, `pnpm test` all green.

## Current-state facts (verified in code)

- **External shape** (`SaveData.ts`): `{ character, world, session }`.
  - `character`: `appearance, stats{level,health,maxHealth}, inventory[], position{x,y,z}, yarn, oxygen, abilities[]`
  - `world`: `currentMapId, activeCats[], resourceNodeCooldowns[], hiddenTerrain[]`
  - `session`: `totalPlaytimeMs`
- **Internal shape** (`GameState.SaveData`, `GameState.ts:55-58`): `{ player, world }` where
  `player` mirrors `character` (minus the `character` rename) and `world.resourceNodes` is the
  internal name for external `world.resourceNodeCooldowns`. `session` is NOT part of internal
  `SaveData` — it is a transient field excluded from `serialize()`.
- **The one rename**: internal `world.resourceNodes` ↔ external `world.resourceNodeCooldowns`
  (`Persistence.ts:28`, `:50`). Everything else is a straight copy plus the `player`→`character`
  section rename.
- **`session` is asymmetric**: `toExternalSaveData` writes `session: { totalPlaytimeMs: 0 }`
  (a constant, not sourced from state — `Persistence.ts:31`); `fromExternalSaveData` drops
  `session` entirely (`Persistence.ts:35-53`). This asymmetry MUST be preserved.
- **Dirty-path granularity differs from converter granularity.** The converter copies
  `player.stats` as a whole object, but `NON_POSITION_PATHS` subscribes to three *leaf* paths:
  `player.stats.health`, `player.stats.level`, `player.stats.maxHealth` (`Persistence.ts:62-64`).
  Dirty paths also use the *internal* name `world.resourceNodes` (`:72`), not the external one.
  `player.position` is deliberately ABSENT from `NON_POSITION_PATHS`; it is subscribed separately
  for throttled tracking (`Persistence.ts:105-110`). The codec model must reproduce this exact set.
- **Emitted key order matters for byte-compat.** `save()` sends the encoder's object directly
  (`Persistence.ts:126-128` parses but upserts the *pre-parse* `saveData`), and
  `setupBeforeUnload()` does `JSON.stringify({ version, saveData })` (`Persistence.ts:187-189`).
  `JSON.stringify` emits keys in insertion order, so the codec must insert keys in the current
  order: character `{appearance, stats, inventory, position, yarn, oxygen, abilities}`, world
  `{currentMapId, activeCats, resourceNodeCooldowns, hiddenTerrain}`, session `{totalPlaytimeMs}`.
- **No on-disk save fixtures exist.** The only "fixtures" are inline object literals:
  `validExternalSaveData()` in `Persistence.test.ts:15-34` and `validSaveData()` in
  `load-restore.test.ts:258-278`. "Existing fixtures load unchanged" means these literals must
  still `schema.parse` and decode identically.
- **`node_${x}_${z}` cooldown-id convention** lives in the spawner, not the codec
  (`Game.ts:689-690`: `this._nodeIdMap.set(\`node_${x}_${z}\`, entity)`), and is echoed by
  ADR-0002 §5. The codec passes `nodeId` strings through opaquely, so this convention is
  untouched — but the plan calls it out so no one "helpfully" reformats ids inside the codec.
- **External consumers of `saveDataSchema`** (must keep working via re-export, see Design):
  `beacon-save/route.ts:5,10`, `server/api/routers/game.ts:6,58`, `migrations.ts:1,55,74`,
  `server/game/upsertGameSave.ts:2` (type only).
- **Test imports of the converters**: `Persistence.test.ts:5` imports
  `toExternalSaveData, fromExternalSaveData` from `Persistence`. Keep these as re-exports so tests
  compile without churn.

## Design — the codec's API

New file `src/game/state/SaveCodec.ts`. Everything derives from ONE ordered descriptor list.

```ts
import { z } from "zod";
import type { SaveData as InternalSaveData } from "../engine/GameState";
import type { SaveData as ExternalSaveData } from "./SaveData";

/** Dirty classification for a saved field. */
type DirtyClass =
  | { kind: "non-position"; paths: readonly string[] } // internal onChange paths
  | { kind: "position" }                                 // throttled separately
  | { kind: "none" };                                    // e.g. session constant

interface SaveField {
  /** Internal GameState path (dot-notation into { player, world }); null for constants. */
  readonly internalPath: string | null;
  /** External save-data path (dot-notation into { character, world, session }). Depth-2. */
  readonly externalPath: string;
  /** Zod schema for this leaf/subtree (used to build saveDataSchema). */
  readonly schema: z.ZodTypeAny;
  /** How this field participates in dirty tracking. */
  readonly dirty: DirtyClass;
  /** Constant value used on encode when internalPath is null (e.g. session.totalPlaytimeMs = 0). */
  readonly encodeConstant?: unknown;
}

// Declared in the exact key order the external shape must serialize in.
export const SAVE_FIELDS: readonly SaveField[] = [ /* ...see below... */ ];
```

Descriptor list (order is load-bearing for byte-compat):

| internalPath          | externalPath                   | dirty                                                             |
|-----------------------|--------------------------------|------------------------------------------------------------------|
| `player.appearance`   | `character.appearance`         | non-position `["player.appearance"]`                             |
| `player.stats`        | `character.stats`              | non-position `["player.stats.health","player.stats.level","player.stats.maxHealth"]` |
| `player.inventory`    | `character.inventory`          | non-position `["player.inventory"]`                             |
| `player.position`     | `character.position`           | **position**                                                     |
| `player.yarn`         | `character.yarn`               | non-position `["player.yarn"]`                                  |
| `player.oxygen`       | `character.oxygen`             | non-position `["player.oxygen"]`                                |
| `player.abilities`    | `character.abilities`          | non-position `["player.abilities"]`                             |
| `world.currentMapId`  | `world.currentMapId`           | non-position `["world.currentMapId"]`                           |
| `world.activeCats`    | `world.activeCats`             | non-position `["world.activeCats"]`                             |
| `world.resourceNodes` | `world.resourceNodeCooldowns`  | non-position `["world.resourceNodes"]`                          |
| `world.hiddenTerrain` | `world.hiddenTerrain`          | non-position `["world.hiddenTerrain"]`                          |
| `null` (const 0)      | `session.totalPlaytimeMs`      | none                                                             |

Each `schema` is lifted verbatim from the current hand-written `saveDataSchema` (e.g.
`player.stats` → the existing `z.object({ level, health, maxHealth })`; `player.position` → the
existing `vec3Schema`; etc.). Do NOT re-invent the schemas — move the existing ones.

Derived functions:

```ts
// Build external { character, world, session } by iterating SAVE_FIELDS IN ORDER,
// reading internalPath from the internal state (or encodeConstant), writing externalPath.
export function encode(state: InternalSaveData): ExternalSaveData;

// Build internal { player, world } by iterating SAVE_FIELDS, skipping fields with
// internalPath === null (session), reading externalPath, writing internalPath.
export function decode(data: ExternalSaveData): InternalSaveData;

// Group SAVE_FIELDS by top-level section → z.object of second-level keys.
// Produces the SAME object as the current hand-written saveDataSchema.
export function buildSaveDataSchema(): z.ZodObject<...>;

// Flatten every non-position dirty.paths across SAVE_FIELDS. Reproduces NON_POSITION_PATHS.
export const NON_POSITION_DIRTY_PATHS: readonly string[];

// The single position-throttled path ("player.position"), for Persistence's separate subscription.
export const POSITION_DIRTY_PATH = "player.position";
```

Implementation notes for `encode`/`decode`: use small `getAtPath` / `setAtPath` helpers that
build intermediate objects on demand and assign leaves in iteration order (mirror the private
helpers in `GameState.ts:224-241`). Because all `externalPath`s are depth-2 and the list is
ordered, insertion order of the emitted object exactly matches today's literal.

### How existing readers/writers are refactored to go through the codec

- **`SaveData.ts`**: replace the hand-written `saveDataSchema` object literal with
  `export const saveDataSchema = buildSaveDataSchema();`. Keep `CURRENT_VERSION` and
  `export type SaveData = z.infer<typeof saveDataSchema>` unchanged. All external importers
  (`beacon-save`, `game` router, `migrations`, `upsertGameSave`) keep importing from `SaveData.ts`
  untouched — the schema is byte-identical, just sourced from the codec.
  - To avoid an import cycle (`SaveCodec` imports the `SaveData` *type* from `SaveData.ts`), have
    `SaveCodec` import only `import type { SaveData } from "./SaveData"` (type-only imports are
    erased and do not create a runtime cycle) OR define the `ExternalSaveData` structural type
    inside `SaveCodec` and let `SaveData.ts` re-derive its type from the built schema. Prefer the
    type-only import; verify `pnpm build` shows no cycle warning.
- **`Persistence.ts`**:
  - Replace the bodies of `toExternalSaveData` / `fromExternalSaveData` with
    `export const toExternalSaveData = encode;` and `export const fromExternalSaveData = decode;`
    (thin re-exports preserve the test imports at `Persistence.test.ts:5`).
  - Replace the local `NON_POSITION_PATHS` constant (`:60-73`) with an import of
    `NON_POSITION_DIRTY_PATHS` from the codec; the constructor loop (`:97-103`) is otherwise
    unchanged. Replace the literal `"player.position"` at `:106` with `POSITION_DIRTY_PATH`.
  - `POSITION_DIRTY_THROTTLE_MS` (`:75`) and all save/load/autosave/beacon logic stay byte-for-byte
    the same. This is a pure extraction, not a behavior change.

## Behavior-preservation constraints

1. **External save-data shape stays byte-compatible.** Same keys, nesting, and *insertion order*.
   Proven by a `JSON.stringify` equality assertion (see Test plan) and the reviewer's before/after
   diff (see Review process).
2. **NO migration.** `CURRENT_VERSION` stays `"0.1"`; `MIGRATIONS` stays empty; `migrateIfNeeded`
   is not touched. Existing DB saves decode through the same schema.
3. **Dirty-throttling identical.** `NON_POSITION_DIRTY_PATHS` must equal the current
   `NON_POSITION_PATHS` set exactly (order-insensitive, but same members). Position stays on its
   own throttled subscription. Assert set equality in a test.
4. **`node_${x}_${z}` convention preserved.** The codec treats `nodeId` as an opaque string; the
   spawner in `Game.ts:689-690` is not modified. Call this out in the PR body so reviewers don't
   expect codec-side id handling.
5. **`session` asymmetry preserved.** Encode injects `{ totalPlaytimeMs: 0 }`; decode drops it.

## Test plan

New file `src/game/__tests__/state/SaveCodec.test.ts` (create the `state/` test dir to mirror
source layout, per CLAUDE.md). Use plain objects — no Three.js/DOM imports needed.

1. **Round-trip `decode(encode(state))`** — build a fully-populated internal `SaveData` (non-default
   yarn, stats, a multi-item inventory, non-zero position, non-empty `activeCats`,
   `resourceNodes`, `hiddenTerrain`, `abilities`, `appearance`) and assert
   `decode(encode(state))` deep-equals it (`expect(...).toEqual(state)`). This fails if a field is
   declared on only one side.
2. **Reverse round-trip `encode(decode(external))`** — start from the `validExternalSaveData()`
   literal shape; assert `encode(decode(external))` deep-equals the original external object
   (guards the `resourceNodes`↔`resourceNodeCooldowns` rename and `session` injection).
3. **Byte-compatibility assertion** — assert
   `JSON.stringify(encode(state)) === JSON.stringify(expectedLiteral)` for a known input, where
   `expectedLiteral` is the current hand-authored external object with keys in today's order. This
   locks key *order*, not just membership. Also assert the top-level `Object.keys` order is
   `["character","world","session"]` and each section's key order matches the table above.
4. **Schema equivalence** — `buildSaveDataSchema().parse(validExternalSaveData())` succeeds; a
   malformed object (e.g. `stats.level = 99`) is rejected, matching the current schema's
   `.int().min(0).max(10)` bound (`SaveData.ts:12`).
5. **Dirty-set equality** — assert
   `new Set(NON_POSITION_DIRTY_PATHS)` equals the literal set of the 12 current
   `NON_POSITION_PATHS` members, and that it does NOT contain `"player.position"`. Assert
   `POSITION_DIRTY_PATH === "player.position"`.
6. **Break-it verification (documented, run during step 6 above, not committed)** — deleting a
   descriptor breaks tests 1 and 3; misclassifying position breaks test 5.

  (`:353-396`), beacon tests (`:402-467`).

1. **Byte-compat diff (primary gate).** Before starting, capture a baseline: in a throwaway node

## Decision / ADR checkpoint

Byte-compatibility of the external save shape is a durable architectural invariant and should be
recorded, following the ADR-0002 precedent (which already froze the `node_${x}_${z}` id convention
"so existing persisted saves decode correctly without migration", ADR-0002 §5).

- **Add `docs/adr/0003-save-codec-single-owner.md`** (next number after 0001/0002): record that
  (a) `SaveCodec.SAVE_FIELDS` is the single source of truth for the save-data shape; (b) the
  external `{ character, world, session }` shape is FROZEN and byte-compatible with pre-#28 saves —
  no migration; (c) shape changes now go through `CURRENT_VERSION` + `MIGRATIONS`, never by editing
  the external key layout in place; (d) the `resourceNodes`↔`resourceNodeCooldowns` rename and the
  `session.totalPlaytimeMs=0` injection are intentional and codified in the descriptor list.
- **Proof of byte-compatibility** is the executable test #3 (JSON.stringify equality) plus the
  reviewer's before/after diff. Reference that test path in the ADR so the invariant is
  continuously enforced, not just asserted once.
