## 1. Goal & acceptance criteria

### Goal
Consolidate the Cat Companion lifecycle — **summon → active → (expiry) → despawning → destroyed**,
plus cap eviction, the yarn-refund rule, and the despawn animation phase — under **one owner**
(the deepened `CatCompanionManager`). The per-cat systems (Zoomies, Curiosity, Pounce) shrink to
pure **effects**: they read cat state through a small read-only seam and apply their effect
(speed trail, terrain reveal, pounce launch). They no longer detect expiry, call `dismiss()`,
or destroy entities. Curiosity's "wait for the terrain fade before despawning" becomes an
explicit **hold-despawn affordance** on the lifecycle interface instead of a private
deferred-dismiss queue.

Today the lifecycle has **four owners**:
1. `CatAISystem` — flips `CatBehavior.state` (`Idle→Active→Expired`).
2. Per-cat systems — each detects `Expired` and calls `manager.dismiss()` (Curiosity via a private
   `pendingDismiss` queue after a terrain fade).
3. `CatCompanionManager.dismiss()` — teardown + yarn refund.
4. `VisualEffectsSystem._updateScaleAnimations` — fires `world.destroyEntity` when the scale-down
   tween finishes.

### Acceptance criteria (from the issue)
- [ ] One module owns every cat state transition, the expiry timers, the refund rule, and the final
      entity destruction.
- [ ] Per-cat systems (Zoomies, Curiosity, Pounce) contain **no** `dismiss`/`destroy` calls and
      **no** expiry detection; they read cat state through the lifecycle module's interface.
- [ ] `VisualEffectsSystem` no longer calls `world.destroyEntity` for cats.
- [ ] A **unit test** covers `summon → expire → refund → destroy` against the lifecycle module's
      interface **alone**, without wiring four systems together.
- [ ] Curiosity's fade-out-before-despawn behavior still works (covered by an **integration test**).
- [ ] Cat restore from a saved game (`world.activeCats`) behaves identically, including yarn accounting.
- [ ] `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm build` all pass.

## 4. Design

### 4.1 The read-only seam (`CatStateView`)
```ts
// src/game/cats/CatLifecycle.ts
import type { Entity } from "../ecs/Entity";
import type { CatState } from "../ecs/components/CatBehavior";

/** Read-only lifecycle seam consumed by per-cat effect systems.
 *  Effects READ state and may request a despawn HOLD; they never drive
 *  transitions, teardown, or destruction. */
export interface CatStateView {
  /** Current lifecycle state, or undefined if the entity is not a tracked cat. */
  getCatState(entity: Entity): CatState | undefined;
  /** Convenience: true iff getCatState(entity) === "Active". */
  isActive(entity: Entity): boolean;
  /** Prevent the owner from despawning an Expired cat until released.
   *  Ref-counted so multiple effects can hold the same cat safely. */
  holdDespawn(entity: Entity): void;
  releaseDespawn(entity: Entity): void;
}
```
`CatCompanionManager implements CatStateView`. Effect systems take a `CatStateView` in their
constructor, not the concrete manager — cleaner dependency direction and trivially mockable.

### 4.2 State machine (add `"Despawning"`)
`CatState = "Idle" | "Active" | "Cooldown" | "Expired" | "Despawning"`.
- `Idle → Active`: first `update()` tick after summon (unchanged from CatAISystem).
- `Active → Expired`: duration cats only, when `stateTimer >= def.behavior.duration` (unchanged logic).
- `Expired → Despawning`: **owner-driven**, only when there is no active despawn hold. This is the
  moment teardown + refund-rule + scale-down animation happen. `CatBehavior` is then removed (so
  effects skip the entity during the animation, exactly as `dismiss()` does today).
- `Despawning → (destroyed)`: owner's despawn timer elapses → `world.destroyEntity`.

### 4.3 Owner internals added to `CatCompanionManager`
```ts
private readonly despawning = new Map<Entity, number>();   // entity → seconds remaining
private readonly despawnHolds = new Map<Entity, number>(); // entity → hold ref-count
private static readonly DESPAWN_SECONDS = 0.2;             // matches the scale-down tween
```

### 4.4 The `update(dt)` driver (absorbs CatAISystem + VisualEffectsSystem's destroy)
Iterates the **world query** `query("CatBehavior", "Transform")` (identical to CatAISystem — so
cats spawned by test helpers, not just via `summon()`, are still driven), then advances despawn timers:

```
update(dt):
  for entity in world.query("CatBehavior","Transform"):
    if !world.isAlive(entity): continue
    behavior = getComponent(CatBehavior)
    duration = CAT_REGISTRY.get(behavior.catType)?.behavior.duration
    switch behavior.state:
      "Idle":    behavior.state = "Active"
      "Active":  if duration !== undefined:
                   behavior.stateTimer += dt
                   if behavior.stateTimer >= duration: behavior.state = "Expired"
      "Expired": if !this.isHeld(entity): this.beginDespawn(entity, { refund: false })
      "Cooldown"/"Despawning": no-op
  // advance despawn timers (destruction authority)
  for [entity, remaining] of this.despawning:
    next = remaining - dt
    if next <= 0: world.destroyEntity(entity); this.despawning.delete(entity)
    else: this.despawning.set(entity, next)
```

**Two-tick guarantee for holds.** Expiry (`Active→Expired`) and despawn (`Expired→Despawning`)
happen on **different `update()` calls**: the `switch` sets `Expired` and does not fall through.
Effect systems run **after** the owner in the fixed-step loop (unchanged ordering), so on the tick
the owner sets `Expired`, CuriositySystem runs, sees `Expired` via the seam, begins its fade, and
calls `holdDespawn`. On the **next** owner tick the cat is `Expired && held` → the owner waits. When
the fade finishes, CuriositySystem calls `releaseDespawn`; the following owner tick despawns. This
removes the private `pendingDismiss` queue entirely.

> Behavior note: for cats with **no** holding effect (Zoomies), despawn now starts one fixed tick
> (1/60 s) later than today (today CatAISystem sets Expired and ZoomiesSystem dismisses in the same
> tick). This is imperceptible and does not change gameplay feel; it is recorded in §9.

### 4.5 `beginDespawn()` — shared teardown (extracted from today's `dismiss()`)
```
private beginDespawn(entity, { refund }):
  if this.despawning.has(entity): return           // idempotent guard
  behavior = getComponent(CatBehavior)
  if refund && behavior && behavior.state !== "Expired":
      gameState.addYarn(behavior.yarnCost)          // refund rule preserved
  removePhysicsBody(entity); destroyTrail(entity)   // physicsHandles / trailEntities maps
  companions.delete(entity)
  removeComponent(entity,"CatBehavior")             // effects skip during animation (as today)
  removeComponent(entity,"CuriosityReveal")
  addComponent(entity, createCatScaleAnimation(1,0,0.2))   // pop-out; VisualEffects tweens only
  this.despawning.set(entity, DESPAWN_SECONDS)      // owner destroys when this elapses
  this.despawnHolds.delete(entity)
  if catType !== undefined: eventBus.emit(cat:dismissed)
```

### 4.6 `dismiss()` — the manual entry point (unchanged signature/semantics)
`dismiss(entity)` remains public (called by HUD/input to remove a cat early). It computes the refund
exactly as today (`refund: state !== "Expired"`) and funnels into `beginDespawn`:
```
dismiss(entity):
  if !world.isAlive(entity): companions.delete(entity); return
  if this.despawning.has(entity): return           // replaces the destroyOnComplete guard
  const state = getComponent(CatBehavior)?.state
  this.beginDespawn(entity, { refund: state !== "Expired" })
```
`summon()` is **unchanged** except the pop-in animation call drops the now-removed flag:
`createCatScaleAnimation(0, 1, 0.2)`.

### 4.7 `CatStateView` method bodies
```
getCatState(entity): if despawning.has(entity) return "Despawning";
                     return getComponent(CatBehavior)?.state
isActive(entity):    return getCatState(entity) === "Active"
holdDespawn(entity): despawnHolds.set(entity, (despawnHolds.get(entity) ?? 0) + 1)
releaseDespawn(entity): n = (despawnHolds.get(entity) ?? 0) - 1;
                        n <= 0 ? despawnHolds.delete(entity) : despawnHolds.set(entity, n)
isHeld(entity):      (despawnHolds.get(entity) ?? 0) > 0   // private
```

### 4.8 Per-cat effect systems become pure effects
- **ZoomiesSystem**: constructor takes `CatStateView` instead of `CatCompanionManager`. Delete the
  `behavior?.state === "Expired"` → `dismiss()` block (lines 78–83). Keep the orphan-trail cleanup
  (`!world.isAlive(trail.catEntity)` → destroy trail) as a harmless safety net. Gate the overlap /
  SpeedBoost on `catState.isActive(trail.catEntity)`.
- **CuriositySystem**: constructor takes `CatStateView` (+ existing `sceneManager`, `eventBus`).
  Replace `pendingDismiss` with a `fadingCats: Set<Entity>`. On `getCatState(cat) === "Expired"` and
  not yet fading → `beginHideRevealedTerrain(reveal)` + `catState.holdDespawn(cat)` +
  `fadingCats.add(cat)`. On `Active` && `reveal.revealedEntities.length === 0` → reveal (unchanged).
  Keep `animateOpacity`. Replace `flushDismissals` with `flushFades`: when a fading cat's terrain has
  finished fading (`currentOpacity` all 0 / dead), reset `reveal.revealedEntities = []`,
  `catState.releaseDespawn(cat)`, `fadingCats.delete(cat)`. **No `dismiss()` call.**
- **PounceSystem**: add a `CatStateView` constructor arg. Replace `behavior.state !== "Active"`
  (line 70) with `if (!catState.isActive(catEntity)) continue;`. Everything else unchanged (Pounce is
  permanent, never expires).

### 4.9 VisualEffectsSystem
`_updateScaleAnimations` keeps tweening `transform.scale{X,Y,Z}` for both pop-in and pop-out. On
completion it **always** `removeComponent(entity, "CatScaleAnimation")` — the `entitiesToDestroy`
array and the `destroyEntity` branch are removed. The pop-out visual (scale→0) and the owner's 0.2 s
despawn timer both run on real `dt`, so the entity is destroyed ~as the tween reaches 0, visually
identical to today. `_updateShadows` is unchanged (it already prunes shadows when `CatBehavior`
disappears, which now happens at `beginDespawn`, exactly as it did at `dismiss` before).

### 4.10 Game.ts wiring
- Remove the `catAISystem` field (151) and its construction (248); delete the import.
- Fixed-step loop (708) and debug `tick()` (481): replace `this.catAISystem.update(this.world, dt)`
  with `this.catCompanionManager.update(this.world, dt)` at the **same position** (before the effect
  systems) to preserve ordering.
- Inject the seam into Pounce: `new PounceSystem(this.physics, this.catCompanionManager)`; pass
  `this.catCompanionManager` to Zoomies/Curiosity where they previously received the manager (the

## 5. Behavior-preservation constraints
- **No gameplay change** to zoomies (speed trail + SpeedBoost), curiosity (reveal radius, 0.5 s
  fade, fade-out-before-despawn), or pounce (launch impulse, once-per-landing). Effect math is copied
  verbatim; only the *state read* and *lifecycle trigger* move behind the seam.
- **Yarn accounting unchanged**: refund only when `state !== "Expired"`; expiry consumes yarn; manual
  dismiss of an Active cat refunds. Same `deductYarn`/`addYarn` call sites and amounts.
- **Active-cat save restore unchanged**: `summon()` / `dismiss()` / `isValidPosition()` /
  `getActiveCompanions()` signatures and semantics are identical; `_restoreActiveCats()` (Game.ts
  657–672) is untouched, including the pre-fund → summon → undo-on-failure dance (net yarn Δ = 0).
- **External save-data shape unchanged**: `SaveCodec` `world.activeCats` mapping and the
  `GameState.activeCats` field are untouched. No new persisted fields.
- **`node_${x}_${z}` convention untouched** (ADR-0002 §5) — no resource-node code is modified.
- Cap eviction (`summon` at cap → `dismiss(oldest)` before the placement probe) is unchanged.
- `getActiveCompanions()` still excludes a cat the instant despawn begins (companions.delete in
  `beginDespawn`), preserving existing `not.toContain(entity)` assertions.

## 10. Decision / ADR checkpoint note
This slice is a **structural refactor with an explicit behavior-preservation contract**, so it warrants
a short ADR under `docs/adr/` (single-context convention per CLAUDE.md → `docs/agents/domain.md`).

Draft **ADR-0003: Single lifecycle owner for the Cat Companion**:
- **Context**: lifecycle spread across CatAISystem, per-cat systems, CatCompanionManager, and
  VisualEffectsSystem; "why didn't my cat disappear?" was a four-file trace and no unit test could
  prove a cat dies.
- **Decision**: `CatCompanionManager` owns state transitions, expiry timers, the yarn-refund rule
  (no refund for expired cats), the despawn animation phase, and entity destruction. Per-cat systems
  are pure effects reading state via the `CatStateView` seam; Curiosity's fade-before-despawn uses the
  ref-counted `holdDespawn`/`releaseDespawn` affordance.
- **Preservation record (the checkpoint)**: explicitly record that (a) zoomies/curiosity/pounce
  gameplay is unchanged (effect math copied verbatim, guarded by the migrated system tests), (b)
  active-cat save restore including the yarn pre-fund/refund dance is unchanged (guarded by
  `load-restore.test.ts`), (c) the external save shape (`world.activeCats`) and the `node_${x}_${z}`
  convention are untouched, and (d) the one accepted behavioral delta — despawn for holdless cats
  starts one fixed tick (1/60 s) later — is imperceptible.
- **Consequences**: lifecycle is unit-testable in isolation; the state machine has a single home;
  `CatScaleAnimation.destroyOnComplete` is retired.

If the team prefers not to add an ADR for a refactor, record the same preservation facts in the PR
description and link the guarding tests — but an ADR is the durable, single-context home.
