# Plan: Issue #12 — Prefactor: shared cell↔world coordinate helpers

## Summary & goal

Extract the cell-grid ↔ world-space coordinate formulas that are currently inlined in `MapManager` into a single pure-function module (`src/game/maps/coords.ts`), then route every call site in `MapManager` through those helpers. This is a **zero-behavior-change prefactor**: no game logic changes, no new features, no modifications to any existing test assertion. The motivation is to eliminate the single canonical formula (`-halfW + col*cellSize + cellSize/2`) appearing in multiple places so that future coordinate bugs or extensions have exactly one place to update. The `FLOOR_THICKNESS` constant used in the height rule also moves to `coords.ts` (or is passed as a parameter — see the design choice note below).

#### Exported functions

**`cellToWorld`** — converts a grid (row, col) to world-space center of that cell.

Formula sourced from `MapManager.buildZones()` lines 204–207:
```
const worldX = -halfW + c * cs + width / 2;   // for a 1-cell zone: width = cs
const worldZ = -halfD + r * cs + depth / 2;
```
For a single cell (`width = cs`, `depth = cs`) this simplifies to:
```
worldX = -halfW + col * cellSize + cellSize / 2
worldZ = -halfD + row * cellSize + cellSize / 2
```

Signature:
```typescript
export function cellToWorld(
  col: number,
  row: number,
  cellSize: number,
  mapWidth: number,   // data.size.width
  mapDepth: number,   // data.size.depth
): { x: number; z: number }
```

**`worldToCell`** — converts world (x, z) to grid (col, row). This is the inverse of `cellToWorld` for the per-cell grid.

Formula sourced from `MapManager.getTerrainAt()` lines 120–121:
```typescript
const col = Math.floor((x + size.width / 2) / cellSize);
const row = Math.floor((z + size.depth / 2) / cellSize);
```

Signature:
```typescript
export function worldToCell(
  x: number,
  z: number,
  cellSize: number,
  mapWidth: number,
  mapDepth: number,
): { col: number; row: number }
```

**`cellMeshGeometry`** — returns the box height and center-Y for a terrain entity, encoding the "elevated box or thin floor slab" rule.

Formula sourced from `MapManager.createTerrainEntity()` lines 228–231:
```typescript
const boxHeight = cell.height > 0 ? cell.height : FLOOR_THICKNESS;
const centerY   = cell.height > 0 ? cell.height / 2 : -FLOOR_THICKNESS / 2;
```

Signature:
```typescript
export function cellMeshGeometry(
  cellHeight: number,
  floorThickness?: number,   // defaults to FLOOR_THICKNESS
): { boxHeight: number; centerY: number }
```

The `floorThickness` parameter defaults to the module-level `FLOOR_THICKNESS` constant, so callers passing nothing get identical behaviour to the pre-refactor code.

## Files to modify

### `src/game/maps/MapManager.ts`

Three inlined coordinate sites need to be replaced; the `FLOOR_THICKNESS` constant can be removed (re-exported from `coords.ts`).

**Import addition** (top of file, after existing ECS imports):
```typescript
import { cellToWorld, worldToCell, cellMeshGeometry, FLOOR_THICKNESS } from "./coords";
```

**Site 1 — `buildZones()` lines 155–207**: zone world-position calculation.

Current code (lines 204–207):
```typescript
const width = (c2 - c + 1) * cs;
const depth = (r2 - r + 1) * cs;
const worldX = -halfW + c * cs + width / 2;
const worldZ = -halfD + r * cs + depth / 2;
```

After refactor — the per-zone center cannot be expressed as a single `cellToWorld` call because merged zones span multiple cells. The correct replacement uses `cellToWorld` to compute the **top-left cell center** and then offset by the extra half-span:

```typescript
const width = (c2 - c + 1) * cs;
const depth = (r2 - r + 1) * cs;
const topLeft = cellToWorld(c, r, cs, data.size.width, data.size.depth);
const worldX = topLeft.x + (width - cs) / 2;
const worldZ = topLeft.z + (depth - cs) / 2;
```

Alternatively (and equivalently, for clarity), keep the existing arithmetic but delegate only the single-cell sub-formula:
```typescript
const width = (c2 - c + 1) * cs;
const depth = (r2 - r + 1) * cs;
// Use helper for left-edge offset, then add half-zone width
const leftEdge = -halfW + c * cs;
const topEdge  = -halfD + r * cs;
const worldX = leftEdge + width / 2;
const worldZ = topEdge + depth / 2;
```

**Preferred approach for this refactor**: Route the *single-cell* case through `cellToWorld` and derive the merged-zone center algebraically from it. This keeps the helper usage honest (the helper is correct for single cells; a merged zone is a derived composite). The formula below is equivalent:

```typescript
const width = (c2 - c + 1) * cs;
const depth = (r2 - r + 1) * cs;
const { x: cellX, z: cellZ } = cellToWorld(c, r, cs, data.size.width, data.size.depth);
// A merged zone starting at (c,r) of size (c2-c+1)×(r2-r+1) cells:
// its center is the top-left cell center + half the remaining cells' span.
const worldX = cellX + ((c2 - c) * cs) / 2;
const worldZ = cellZ + ((r2 - r) * cs) / 2;
```

Verify numerically: for a single cell (c2 = c, r2 = r) this yields `cellX + 0 = cellX`. For two cells (c2 = c+1): `cellX + cs/2`, which equals `-halfW + c*cs + cs/2 + cs/2 = -halfW + c*cs + cs` — correct for a two-cell merged zone.

**Also remove** the now-redundant `halfW` / `halfD` variables at lines 155–156 if they are no longer needed after the refactor (they may still be needed if kept as intermediate names — make the judgment call during implementation; either is fine as long as `coords.ts` owns the formula).

**Site 2 — `getTerrainAt()` lines 120–121**: terrain lookup.

Current:
```typescript
const col = Math.floor((x + size.width / 2) / cellSize);
const row = Math.floor((z + size.depth / 2) / cellSize);
```

After:
```typescript
const { col, row } = worldToCell(x, z, cellSize, size.width, size.depth);
```

**Site 3 — `createTerrainEntity()` lines 228–231**: box height / center-Y rule.

Current:
```typescript
const boxHeight = cell.height > 0 ? cell.height : FLOOR_THICKNESS;
const centerY   = cell.height > 0 ? cell.height / 2 : -FLOOR_THICKNESS / 2;
```

After:
```typescript
const { boxHeight, centerY } = cellMeshGeometry(cell.height);
```

**`FLOOR_THICKNESS` constant**: remove the `const FLOOR_THICKNESS = 0.2;` at line 61 and import it from `./coords` instead (it is already added in the import above). If `FLOOR_THICKNESS` is referenced elsewhere in the file other than `createTerrainEntity`, it continues to work via the import.

#### Test group 1: `cellToWorld` / `worldToCell` inverse property

For every (row, col) in a sample grid, assert that `worldToCell(cellToWorld(col, row, ...), ...)` returns the original (col, row).

```typescript
it("worldToCell(cellToWorld(col, row)) === (col, row) for TestMap params", () => {
  const cs = 2, w = 60, d = 60;
  for (let r = 0; r < 30; r++) {
    for (let c = 0; c < 30; c++) {
      const { x, z } = cellToWorld(c, r, cs, w, d);
      const { col, row } = worldToCell(x, z, cs, w, d);
      expect(col).toBe(c);
      expect(row).toBe(r);
    }
  }
});
```

Also assert the reverse for a representative set of world points (centre of each cell):
```typescript
it("cellToWorld(worldToCell(x, z)) rounds back to the same cell center", () => {
```

## Risks / unknowns

1. **`buildZones()` multi-cell zone formula**: The merged-zone center (`worldX`, `worldZ`) is a composite of the per-cell helper and extra offset arithmetic. The proposed replacement (`cellX + ((c2 - c) * cs) / 2`) is algebraically equivalent but should be verified with a concrete numeric example during implementation before committing. An off-by-one in this path would silently misplace all merged terrain zones.

2. **`FLOOR_THICKNESS` relocation**: It is currently declared in `MapManager.ts` as a module-level `const` (line 61). After moving it to `coords.ts`, it is imported back. If any other file in the future imports it from `MapManager`, that import would break. Audit the codebase for any `FLOOR_THICKNESS` references outside `MapManager.ts` before removing it (`grep -rn "FLOOR_THICKNESS" src/`). At time of investigation: zero other files reference it.

3. **`halfW` / `halfD` variables in `buildZones()`**: These are computed once (lines 155–156) and used both in the zone-center calculation and implicitly in the helper call. After refactor, check whether they are still needed or can be removed entirely.

4. **`Game.ts` `spawnTestMapResourceNodes()` comment and formula**: `Game.ts` lines 604–605 document a cell-center formula inline (`x = -29 + col*2`) in a comment (not as runnable code). This is not a call site but it is an inconsistency: the comment expresses the same formula differently. This issue does **not** require `Game.ts` to be modified (it is a comment in a method that hand-codes coordinates as literals), but the implementation agent should flag it for a follow-up. It is out of scope for this prefactor.

5. **NavigationOverlay `worldToPixel`**: NavigationOverlay implements its own world-to-pixel transform (different from grid indexing — it maps world floats to canvas pixels). It does **not** duplicate the cell-grid formulas. No changes needed there.

6. **Test count**: The issue references 724 passing tests. Verify this count before starting so the post-refactor gate comparison is accurate.
