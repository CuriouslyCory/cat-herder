**Branch:** `feat/25-entity-prefabs` (worktree `../wt-25`, off `feat/architecture-deepening`)
**Type:** Behavior-preserving refactor (no gameplay change, no save-shape change)
**Depends on:** none (Wave 1). Enables #26 (cat lifecycle).

## 1. Goal & Acceptance Criteria

### Goal
Extract every entity spawn *recipe* (the ECS component/mesh assembly for player, resource
node, yarn pickup, and cat companion) into a single **prefab module of pure functions**. Today
these recipes live in three drifting copies:

1. **Production** — private methods on `Game` (`spawnPlayer`, `spawnMapResourceNodes`,
   `spawnMapYarnPickups`) and cat assembly inside `CatCompanionManager.summon`.
2. **Debug UI** — `DebugMenu.applySpawnResourceNode` hand-assembles the same ResourceNode entity.
3. **Tests** — `src/game/__tests__/helpers/entityFactories.ts` maintains a parallel copy.

The drift is already a latent bug: the test factory builds Velocity as
`{ type: "Velocity", x: 0, y: 0, z: 0 }` (`entityFactories.ts:24`) while the real component
is `{ type: "Velocity", dx, dy, dz }` (`src/game/ecs/components/Velocity.ts:3-13`). No test
runs `MovementSystem` over a factory-built player, so nothing catches it. `MovementSystem`
reads `velocity.dx/dy/dz` (`MovementSystem.ts:127-143, 187-211`); against the malformed shape
those reads are `undefined` → `moveToward(undefined, …)` → `NaN`.

### Acceptance Criteria (from the issue, made concrete)
- [ ] **AC1** A single prefab module owns all entity spawn recipes; `Game` contains no inline
  component or mesh-config recipes for player / resource node / yarn pickup.
- [ ] **AC2** Test helpers construct entities **through the same prefab functions** — no parallel
  component recipe remains in `entityFactories.ts` for player / resource node / yarn pickup / cat.
- [ ] **AC3** The malformed Velocity shape is gone (prefab uses `createVelocity()`), and **at least
  one test runs `MovementSystem` over a prefab-built player** — a test that fails against the old
  `{x,y,z}` Velocity (drift caught by construction).
- [ ] **AC4** `DebugMenu.applySpawnResourceNode` uses the prefab module (no hand-assembled ECS
  components in UI code).
- [ ] **AC5** Resource-node cooldown ids remain **`node_${x}_${z}`**; existing save-restore
  behavior unchanged (`integration/load-restore.test.ts` still green). **ADR-0002 §5.**
- [ ] **AC6** Resource-node and yarn-pickup prefabs stay **`MapData`-driven** (consume
  `MapDataResourceNode` / `MapDataYarnPickup` fields). **ADR-0002 §3.**
- [ ] **AC7** Prefab functions have unit tests that run **headlessly** (no DOM, no Three.js).
- [ ] **AC8** `pnpm build`, `pnpm lint`, `pnpm typecheck`, `pnpm test` all green.

## 3. Design — the prefab module

### 3.1 Location & files
Create **`src/game/ecs/prefabs.ts`** (single file; the four recipes are small and cohesive).
It sits in `ecs/` because it depends only on ECS components + `PhysicsEngine` +
`SceneManager`'s `MeshConfig` **type** — no DOM, no Three.js runtime. Import `MeshConfig` and
`PhysicsEngine` as `import type` so the module stays headless.

> Rationale for one module over a `prefabs/` folder: keeps the "one source of truth" literal and
> discoverable; the file is ~150 lines. Split later only if cat assembly (issue #26) grows it.

### 3.2 Design principle — two concerns, one call
Each prefab is a **pure function**: takes explicit dependencies + params, creates the entity,
adds ECS components, and — **only when a `PhysicsEngine` is supplied** — registers the physics
body. Physics is optional so:
- Production passes `physics` (bodies needed for movement/collision).
- Headless component tests and the existing swimming/load-restore factories can omit it
  (they never needed a body) — keeping those tests behavior-identical.

This mirrors the issue's "accept their dependencies (world, physics engine, etc.)".

### 3.3 API

```ts
// src/game/ecs/prefabs.ts
import type { World } from "./World";
import type { Entity } from "./Entity";
import type { PhysicsEngine } from "../engine/PhysicsEngine";
import type { MeshConfig } from "../engine/SceneManager";
import type { ResourceType } from "../types";
import type { MapDataResourceNode, MapDataYarnPickup } from "../maps/MapData";
import type { CatDefinition } from "../cats/CatDefinition";
// + create* component factories (Transform, Velocity, PlayerControlled, Renderable,
//   Collider, ResourceNode, YarnPickup, CatBehavior) and RESOURCE_CONFIGS from config

// ── Player ────────────────────────────────────────────────────────────────
export interface PlayerPrefabOptions {
  position: { x: number; y: number; z: number };
  /** Visual + size from CharacterCreator. Defaults match Game.spawnPlayer. */
  appearance?: { shape?: MeshConfig["geometry"]; sizeScale?: number; colorHex?: string };
  /** Collider/body radius. Defaults to runtimeConfig.collisionRadius. */
  collisionRadius?: number;
  /** When provided, registers a dynamic physics body positioned at `position`. */
  physics?: PhysicsEngine;
  /** Enable rim-light on the Renderable (prod passes runtimeConfig.visual.rimLighting). */
  rimLight?: boolean;
}
export function spawnPlayerEntity(world: World, opts: PlayerPrefabOptions): Entity;

// ── Resource node ───────────────────────────────────────────────────────────
export interface ResourceNodePrefabOptions {
  node: MapDataResourceNode;        // {x, z, type, respawnTime} — MapData-driven (ADR-0002 §3)
  physics?: PhysicsEngine;
}
/** Cooldown id is `node_${x}_${z}` — returned so callers can register it. ADR-0002 §5. */
export function spawnResourceNodeEntity(
  world: World,
  opts: ResourceNodePrefabOptions,
): { entity: Entity; nodeId: string };

export function resourceNodeId(x: number, z: number): string; // `node_${x}_${z}` — single source

// ── Yarn pickup ─────────────────────────────────────────────────────────────
export function spawnYarnPickupEntity(
  world: World,
  opts: { pickup: MapDataYarnPickup; physics?: PhysicsEngine },
): Entity;

// ── Cat companion (component assembly only; seam for #26) ─────────────────────
export interface CatPrefabOptions {
  definition: CatDefinition;
  position: { x: number; y: number; z: number };
  centerY: number; owner: Entity;
  halfHeight: number; xzHalfExtent: number;
}
/** Adds Transform, Renderable(def.meshConfig), Collider, CatBehavior. Returns entity.
 *  Does NOT do yarn/cap/physics/trail/curiosity — those stay in CatCompanionManager. */
export function assembleCatEntity(world: World, opts: CatPrefabOptions): Entity;
```

**Key invariants baked in:**
- `spawnPlayerEntity` uses `createVelocity()` → correct `{dx,dy,dz}` (kills the drift).
- `resourceNodeId(x,z)` is the ONLY place the `node_${x}_${z}` template string exists.
- Resource-node `gatherTime`/`yieldAmount` come from `RESOURCE_CONFIGS[type]`; `respawnTime`
  from `node.respawnTime` — identical to `Game.ts:656,686`.
- Color/geometry choices lifted verbatim from `Game.ts:638-642, 663-670` (nodes),
  `708-716` (yarn), `595-605` (player).

## 4. Behavior-preservation constraints

1. **No gameplay change.** Component field values must byte-match the current recipes. Diff each
   `createRenderable(...)` / `createCollider(...)` argument against the originals.
2. **`node_${x}_${z}` unchanged** (AC5, ADR-0002 §5). `resourceNodeId` produces the exact string;
   `Game._nodeIdMap` keys and `_applyResourceNodeCooldowns` matching are untouched.
3. **MapData-driven** (AC6, ADR-0002 §3). Prefabs read `MapDataResourceNode`/`MapDataYarnPickup`;
   no positions are hardcoded in the prefab.
4. **No external save-data shape change.** `SaveData` / `Persistence` are not touched. The
   cooldown round-trip still keys on the same node ids.
5. **DebugMenu numeric note (decide, don't silently "fix"):** Debug's local maps
   (`DebugMenu.ts:337-351`) use `GATHER_TIME` 1.5/1.5/2.0 and `RESPAWN_TIME` 30/45/60 — these
   **already equal** `RESOURCE_CONFIGS` (`config.ts:176-178`), and colors match
   (`#7bc67e`/`#8b6355`/`#4fc3f7`). Debug's collider is `isStatic:true,isTrigger:true,layer:1,mask:0`,
   identical to prod. So routing Debug through the prefab is behavior-preserving. Confirm this
   equality during review; if any value *had* differed we would preserve the Debug value via an
   explicit override param — never change gameplay to make code converge.
6. **Additive component change to test factories is safe.** Delegating `entityFactories.spawnPlayer`
   to the prefab means player entities in `swimming-oxygen` / `load-restore` gain Renderable +
   Collider components they didn't have. Those tests query by component *presence*
   (`SwimmingState`, `OxygenState`, `PlayerControlled`) and never assert component counts, so this
   is behavior-preserving. Verify by running the suite.

  `gatherTime`/`yieldAmount` from `RESOURCE_CONFIGS[type]` and `respawnTime` from the node.

- `assembleCatEntity` adds Transform/Renderable(def.meshConfig)/Collider/CatBehavior.

### 6.2 New: `src/game/__tests__/systems/MovementSystem.test.ts` (AC3 — the drift catcher)
Headless: `World`, real `PhysicsEngine(eventBus)`, `createMockInputManager()`,
`spawnPlayerEntity(world, {position:{x:0,y:1,z:0}, physics})`, `new MovementSystem(mockInput, physics)`.

```
input.setMovementIntent(1, 0);           // push +X
for (let i=0;i<10;i++) movement.update(world, 1/60);
```
