## Goal

Carve the **map-mutation core** out of `MapEditor` into a new, pure module
`src/game/maps/MapMutationCore.ts`. The core owns the canonical map document —
`name`, `size`, `cellSize`, the canonical `terrain[][]` grid (ADR-0002:
`terrain[row][col]`, row = Z, col = X), and the pure entity records (player
spawn, cat spawns, resource nodes, yarn pickups) — plus every mutation operation
on that data and the `MapData` serialize / deserialize round-trip
(`toMapData()` / `loadFromMapData()`).

`#27` already extracted the persistence cluster into `MapPersistenceController`
and **explicitly reserved** `getMapData` / `loadMapData` / terrain-and-entity
mutation for this issue (see `plans/27.md` "Explicitly out of scope (belongs to
#29)" and the header comment in `MapPersistenceController.ts`). This slice
completes that reservation.

`MapEditor` remains the **view / controller**: the DOM panels, banner, ghost /
preview meshes, mouse/keyboard state machine, mode lifecycle, and — critically —
all Three.js `SceneHandle` bookkeeping (cell meshes and entity marker meshes)
stay in `MapEditor`. It drives the core through a small cell-indexed interface
and reflects the core's returned change-sets into scene meshes. **Observable
editor behavior is unchanged, and the external `MapData` shape is unchanged.**

This is the same behavior-preserving-extraction pattern as `#27`; the analogous
new file is `MapMutationCore.ts` and the analogous new jsdom-free test is
`MapMutationCore.test.ts`.

### Acceptance criteria

1. `src/game/maps/MapMutationCore.ts` imports **nothing** from the DOM
   (`document`, `HTMLElement`, `window`, `requestAnimationFrame`, …) or Three.js
   (`three`, `SceneManager`/`SceneHandle`/`MeshConfig`, `CameraController`). Its
   only imports are `MapData` types, the `TerrainType` / `ResourceType` enums,
   and (optionally) the pure `MapDataSchema` for a self-check. Coordinate
   conversion stays a MapEditor concern (see Design); the core is cell-indexed.
2. `MapEditor` performs **no direct `terrain[][]` mutation and no direct entity
   array mutation**. Every edit routes through a `MapMutationCore` method. (Grep
   proof in Review.)
3. A **load → edit → serialize round-trip** test builds/loads a `MapData`,
   mutates through the core, calls `toMapData()`, and asserts the result parses
   cleanly against `mapDataSchema` (required `resourceNodes` / `yarnPickups`,
   non-empty rectangular `terrain`).
4. Editor behavior is **unchanged**: the existing `MapEditor.test.ts` interaction
   suites still pass (changed only at the delegation seam), and the **jsdom
   surface shrinks** — pure terrain/entity-data assertions move OUT of the
   document-stub-scaffolded `MapEditor.test.ts` and INTO the scaffold-free
   `MapMutationCore.test.ts`.
5. `MapData.ts`, `MapDataSchema.ts`, and the tRPC `map` router are **untouched**.
6. `pnpm build`, `pnpm lint`, `pnpm typecheck`, `pnpm test` all pass.

> **On "jsdom":** `vitest.config.ts` sets `environment: "node"` for the whole
> suite — there is no real jsdom. In this repo "the jsdom surface" means the
> hand-rolled DOM scaffolding that `MapEditor.test.ts` must stand up to
> instantiate the editor: `vi.stubGlobal("document", …)` (line ~205),
> `makeMockEl()`, `makeMockSceneManager()`, and the `new MapEditor(...)`
> construction. The core test needs **none** of that — it mirrors
> `MapPersistenceController.test.ts`, which imports "only `vitest`, the
> controller module, and pure data/type helpers." Criterion 4 is satisfied by
> reducing the count of tests that require that scaffolding.

## Design

### New file: `src/game/maps/MapMutationCore.ts` (DOM-free, Three.js-free)

Owns the canonical map document as **pure data** and every mutation on it.
Cell-indexed: all mutation methods take `(col, row)` (col = X, row = Z) —
world↔cell conversion stays in MapEditor. Rectangle/move ops **return the list
of affected `{col,row}` cells** so MapEditor can refresh exactly those meshes.

```ts
import type {
  MapData, MapDataResourceNode, MapDataYarnPickup, SpawnPoint, TerrainCell,
} from "./MapData";
import { ResourceType, TerrainType } from "../types";
// Optional (pure) self-validation helper only — NOT required:
// import { mapDataSchema } from "./MapDataSchema";

// Pure constants moved from MapEditor:
export const HEIGHT_MAX = 5;
export const DEFAULT_MAP_SIZE = { width: 30, depth: 30 } as const;
export const DEFAULT_CELL_SIZE = 2;

// Pure entity records — data only, NO SceneHandle:
export interface CorePlayerSpawn { x: number; z: number; }
export interface CoreCatSpawn { x: number; z: number; }
export interface CoreResourceNode { x: number; z: number; type: ResourceType; respawnTime: number; }
export interface CoreYarnPickup { x: number; z: number; yarnAmount: number; }
export interface CellRef { col: number; row: number; }

export class MapMutationCore {
  private _name = "untitled";
  private _size: { width: number; depth: number } = { ...DEFAULT_MAP_SIZE };
  private _cellSize = DEFAULT_CELL_SIZE;
  private _terrain: TerrainCell[][] | null = null;   // canonical terrain[row][col]
  private _playerSpawn: CorePlayerSpawn | null = null;
  private _catSpawns: CoreCatSpawn[] = [];
  private _resourceNodes: CoreResourceNode[] = [];
  private _yarnPickups: CoreYarnPickup[] = [];

  // ── dimensions / reads ───────────────────────────────────────────────
  get size() { return { ...this._size }; }
  get cellSize() { return this._cellSize; }
  get name() { return this._name; }
  getCell(col: number, row: number): TerrainCell | undefined { return this._terrain?.[row]?.[col]; }
  get resourceNodes(): readonly CoreResourceNode[] { return this._resourceNodes; }
  get yarnPickups(): readonly CoreYarnPickup[] { return this._yarnPickups; }
  get catSpawns(): readonly CoreCatSpawn[] { return this._catSpawns; }
  get playerSpawn(): CorePlayerSpawn | null { return this._playerSpawn ? { ...this._playerSpawn } : null; }

  // Pure iterators powering MapEditor's compat views + mesh rebuild:
  *cells(): Iterable<{ col: number; row: number; cell: TerrainCell }> { /* every cell */ }
  *nonDefaultCells(): Iterable<{ col: number; row: number; cell: TerrainCell }> { /* type≠Grass || height≠0 */ }
  *cellsOfType(t: TerrainType): Iterable<{ col: number; row: number; cell: TerrainCell }> { /* Water / Hidden */ }

  // ── lifecycle ────────────────────────────────────────────────────────
  /** Lazily build an all-Grass grid from size/cellSize. Mirrors _ensureTerrain (round()). */
  ensureTerrain(size = this._size, cellSize = this._cellSize): void;
  /** Replace the whole document from MapData (deep-copies terrain rows, copies entity data). */
  loadFromMapData(data: MapData): void;
  /** Drop all document state (terrain + entities). Mirrors the data half of _clearEditorState. */
  clear(): void;

  // ── terrain mutation (cell-indexed; col = X, row = Z) ────────────────
  /** placeBlock rule: keep height if >0 else 0; navigable = type≠Water && type≠Hidden. */
  paintCell(col: number, row: number, type: TerrainType): void;
  setCellType(col: number, row: number, type: TerrainType): void;
  setCellHeight(col: number, row: number, height: number): void; // clamp [0, HEIGHT_MAX]
  resetCell(col: number, row: number): void;                     // {Grass,0,navigable:true}
  moveCell(from: CellRef, to: CellRef): CellRef[];               // clear src, copy to dest; returns affected
  paintWaterRect(a: CellRef, b: CellRef, depth: number): CellRef[];    // {Water,0,navigable:false,depth}
  paintHiddenRect(a: CellRef, b: CellRef, height: number): CellRef[];  // {Hidden,height,navigable:false}

  // ── entity mutation (pure data; returns the record for handle-keying) ─
  setPlayerSpawn(x: number, z: number): CorePlayerSpawn;   // replaces existing
  clearPlayerSpawn(): void;
  addCatSpawn(x: number, z: number): CoreCatSpawn;
  addResourceNode(n: CoreResourceNode): CoreResourceNode;
  addYarnPickup(p: CoreYarnPickup): CoreYarnPickup;
  removeCatSpawn(ref: CoreCatSpawn): void;                 // identity splice (mirrors indexOf)
  removeResourceNode(ref: CoreResourceNode): void;
  removeYarnPickup(ref: CoreYarnPickup): void;

  // ── serialization ────────────────────────────────────────────────────
  /** Exact port of MapEditor.getMapData(): name/size/cellSize, shallow-copied
   *  terrain rows, spawnPoints from playerSpawn+catSpawns, resource/yarn stripped. */
  toMapData(): MapData;
}
```

**Behavior-preservation notes baked into the port:**
- `paintCell` reproduces lines 799-803 exactly (height preserved only when `>0`,
  navigable rule for Water/Hidden). `setCellHeight` reproduces the
  `Math.max(0, Math.min(HEIGHT_MAX, h))` clamp (864).
- `ensureTerrain` uses `Math.round(depth/cellSize) × Math.round(width/cellSize)`
  (1245-1246), all-Grass cells (1251-1257).
- `loadFromMapData` deep-copies terrain rows (`data.terrain.map(r => [...r])`,
  line 511) and copies entity records field-for-field (525-545) minus handles.
- `toMapData` is a line-for-line port of 459-500 (including the `name ??
  "untitled"` default and `terrain: base?.terrain.map(r => [...r]) ?? []`
  fallback, so the pre-init edge is preserved).
- Rectangle ops iterate `minRow..maxRow` / `minCol..maxCol` and **skip
  out-of-range cells** (`if (!terrain[row]?.[col]) continue;`), matching 946-948
  / 1089-1091.

### How MapEditor consumes the core (view/controller)

- Add `private readonly _core = new MapMutationCore();` (parallel to
  `_persistence`). Remove `_mapData`; keep `_mapSize`/`_cellSize` as **world-math
  mirrors** synced from the core on load/ensure (see below) — this avoids
  touching the dozens of `this._cellSize`/`this._mapSize` world-math call sites
  and keeps the diff bounded and behavior-preserving.
- `getMapData()` → `return this._core.toMapData();`
- `loadMapData(data)`:
  1. `this._clearEditorState();` (removes meshes + `this._core.clear()`)
  2. `this._core.loadFromMapData(data);`
  3. `this._mapSize = { ...data.size }; this._cellSize = data.cellSize;`
     (unchanged mirror sync)
  4. rebuild cell meshes: `for (const {col,row} of this._core.nonDefaultCells()) this._setCellMesh(col,row);`
  5. rebuild entity markers from `this._core.playerSpawn / catSpawns /
     resourceNodes / yarnPickups`, storing each returned handle in the entity
     handle registry (below).
- `_ensureTerrain()` → `this._core.ensureTerrain(this._mapSize, this._cellSize);`
- `_setCellMesh(col,row)` → read `const cell = this._core.getCell(col,row);`
  (was `this._mapData?.terrain[row]?.[col]`); mesh code unchanged.
- Each terrain mutation method becomes: snap world→cell via existing
  `_snapToCell` (which wraps `worldToCell`), call the core op, then refresh the
  affected mesh(es) using the returned `CellRef[]` (or the single known cell for
  `paintCell`/`setCell*`/`resetCell`). Example:
  ```ts
  createWaterZone(x1,z1,x2,z2) {
    const a = this._snapToCell(x1,z1), b = this._snapToCell(x2,z2);
    this._core.ensureTerrain(this._mapSize, this._cellSize);
    for (const {col,row} of this._core.paintWaterRect(a,b,this._selectedWaterDepth))
      this._setCellMesh(col,row);
  }
  ```

**Entity handle registry (the key subtlety).** The core owns pure entity data;
Three.js `SceneHandle`s stay in MapEditor. Replace the `_playerSpawn/_catSpawns/
_resourceNodes/_yarnPickups` (data+handle) fields with a
`private _entityHandles = new Map<object, SceneHandle | null>()` keyed by the
**core record identity** returned from `add*`/`setPlayerSpawn`. This preserves
today's identity-based delete/move (`_removeFoundObject` uses `indexOf(found.obj)`
and object identity): the `found.obj` becomes the core record, and MapEditor
looks up its handle in the map. On delete, `this._core.removeResourceNode(rec);
const h = this._entityHandles.get(rec); if (h) scene.removeMesh(h);
this._entityHandles.delete(rec);`.

Public getters keep their exact shape by **zipping** core data with the handle
map, e.g.:
```ts
getResourceNodes(): readonly EditorResourceNode[] {
  return this._core.resourceNodes.map(n => ({ ...n, handle: this._entityHandles.get(n) ?? null }));
}
```
Likewise `getEditorBlocks()` iterates `this._core.nonDefaultCells()` and looks up
`this._cellHandles.get(\`${col},${row}\`)`; `getEditorWaterZones()` /
`getEditorHiddenTerrainZones()` iterate `this._core.cellsOfType(Water|Hidden)`.
(`EditorBlock`/`EditorWaterZone`/`EditorResourceNode` interfaces are unchanged,
so the public API and its tests are preserved.)

> If, during implementation, identity-keying an object `Map` proves awkward for a
> particular handler, the equally valid fallback is index-aligned
> `(SceneHandle | null)[]` arrays mirroring `core.resourceNodes` etc. Either way,
> **no entity data lives in MapEditor** — only handles.

### Why this stays DOM/Three.js-free

The core imports only `MapData` types, the two enums, and (optionally)
`mapDataSchema`. It never references `document`, `SceneManager`, `SceneHandle`,
`MeshConfig`, `CameraController`, or `three`. World↔pixel/mesh math and every
`SceneHandle` stay in MapEditor. This mirrors `MapPersistenceController`, which
is already proven DOM/Three-free.

## ADR-0002 compliance (critical)

ADR-0002 makes `terrain[][]` the single source of truth with canonical
orientation `terrain[row][col]`, row = Z (north→south), col = X (west→east),
consistent with `coords.ts`.

The plan preserves this by construction:
1. **The core stores exactly one grid, `_terrain: TerrainCell[][]`, in canonical
   orientation.** There is no parallel `blocks[]`/`waterZones[]`/
   `hiddenTerrainZones[]` (those were removed in ADR-0002; the editor's compat
   views are *derived* from `terrain[][]`, not stored). Water = `Water` cells
   (with optional `depth`), Hidden = `Hidden` cells — exactly as ADR-0002
   requires.
2. **Every mutation op is indexed `(col, row)` and writes `terrain[row][col]`.**
   The core's internal indexing is `this._terrain[row][col]` everywhere; the
   argument order `(col, row)` matches `worldToCell`'s `{col, row}` return so the
   MapEditor seam can't silently transpose. A dedicated orientation test
   (below) locks this.
3. **`toMapData()` emits schema-valid `MapData`.** It ports the existing
   serializer verbatim, so required `resourceNodes`/`yarnPickups` are always
   present (empty arrays at minimum) and `terrain` stays the rectangular grid
   the schema's superRefine and dimension check demand. The round-trip test
   asserts `mapDataSchema.safeParse(core.toMapData()).success`.
4. **`MapData.ts` / `MapDataSchema.ts` are not modified**, so the canonical
   contract itself is untouched; the core merely honors it.

## Behavior-preservation constraints

- **No change to editor behavior.** Public MapEditor methods keep their
  signatures and effects: `placeBlock`, `createWaterZone`,
  `createHiddenTerrainZone`, `updateSelectedBlockType/Height`,
  `deleteSelectedBlock`, `getEditorBlocks/WaterZones/HiddenTerrainZones`,
  `getResourceNodes/CatSpawns/YarnPickups`, `getMapData`, `loadMapData`,
  move/delete tools. Mesh creation, selection highlight, ghost/preview, DOM
  panels, and mode lifecycle are byte-for-byte unchanged.
- **No change to the external save-data / `MapData` shape.** `getMapData()`
  output is identical field-for-field (verified by the round-trip + a
  deep-equal against the pre-refactor serializer). The tRPC `map` router and
  `MapData`/`MapDataSchema` are untouched.
- **Numeric parity.** Clamp bounds (`[0, HEIGHT_MAX]`), the `>0` height-preserve
  rule, the `navigable` Water/Hidden rule, `round()` dimension math, and
  rectangle bounds/skip logic are ported verbatim.
- **Constructor arity of MapEditor is unchanged** (no new constructor params;
  the core is instantiated internally like `_persistence`).

## Test plan

New file `src/game/__tests__/maps/MapMutationCore.test.ts`, disciplined exactly
like `MapPersistenceController.test.ts`: imports **only** `vitest`,
`MapMutationCore`, `MapData` types, `TerrainType`/`ResourceType`, and
`mapDataSchema`. **No `document` stub, no `makeMockSceneManager`, no
`MapEditor`.** Add a header comment stating that constraint (as #27's test does).

Cases:
- **Terrain ops:** `paintCell` navigable rule — Water/Hidden → `navigable:false`,
  Grass/Dirt/Stone → `true`; height preserved only when `>0`. `setCellHeight`
  clamps below 0 → 0 and above `HEIGHT_MAX` → `HEIGHT_MAX`. `setCellType`
  changes type only. `resetCell` → `{Grass,0,true}`. `moveCell` clears source
  (Grass default) and copies cell to dest; returns both cells.
  `paintWaterRect`/`paintHiddenRect` fill the inclusive rect and return the
  correct `CellRef[]`; out-of-range corners are clipped (no throw).
- **ADR-0002 orientation lock:** on a non-square grid (e.g. width=6,depth=4,
  cellSize=2 → 2 rows × 3 cols), `paintCell(col=2, row=1, Stone)` then assert
  `toMapData().terrain[1][2].type === Stone` **and** `terrain[0]?.[?]` /
  transposed index is untouched — proving row=Z, col=X. Include a comment citing
  ADR-0002.
