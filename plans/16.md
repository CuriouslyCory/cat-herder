play page fetches the active default map at boot time and threads it into the game as `initialMap`.
The game uses `initialMap ?? TestMap` (built-in fallback) so boot stays synchronous and offline-safe.


Table definition:
```ts
export const maps = createTable(
  "map",
  (d) => ({
    id: d.serial().primaryKey(),
    name: d.varchar({ length: 256 }).notNull(),
    mapData: d.jsonb().notNull(),                   // stores MapData; validated on write via mapDataSchema
    isDefault: d.boolean().notNull().default(false),
    ownerUserId: d.varchar({ length: 256 }),        // nullable — null = system/seeded map
    createdAt: d
      .timestamp({ withTimezone: true })
      .default(sql`CURRENT_TIMESTAMP`)
      .notNull(),
    updatedAt: d
      .timestamp({ withTimezone: true })
      .$onUpdate(() => new Date()),
  }),
  (t) => [
    // SINGLE-DEFAULT invariant: at most one row may have isDefault = true.
    // A partial unique index on a constant expression achieves this:
    // the index only covers rows WHERE is_default = true.
    uniqueIndex("map_single_default_idx")
      .on(t.isDefault)
      .where(sql`is_default = true`),
  ],
);
```

**Drizzle syntax verified**: `uniqueIndex(name).on(column).where(sql\`...\`)` —
`IndexBuilder.where(condition: SQL): this` is declared in
`node_modules/drizzle-orm/pg-core/indexes.d.ts` line 67.
`uniqueIndex` is exported from `drizzle-orm/pg-core` (line 78 of same file).

**DB Application Note**: Do NOT run `db:generate`, `db:migrate`, `db:push`, or create a
`drizzle/` directory. The orchestrator applies schema changes via `pnpm db:push`. Editing
`schema.ts` is sufficient. The partial unique index will be pushed by the orchestrator.

### Procedures

#### `getDefaultMap` — PUBLIC

- **Visibility**: `publicProcedure` (players need it at boot; no auth required)
- **Behavior**:
  1. Query `maps` for the row where `isDefault = true`.
  2. If the table is empty (count = 0), seed it: insert TestMap with `isDefault: true`.
     Return the seeded map data immediately (no re-query needed — use a returning clause
     or just return the TestMap constant directly after insert to avoid a second round-trip).
  3. If a default row exists, return `{ id, name, mapData }`.
- **Seeding logic detail**: Check for the default row first. If null, check whether ANY row
  exists (to avoid re-seeding when there are non-default maps but no default set — edge case
  that shouldn't happen given the invariant, but defensive). The simplest approach: attempt
  insert with `onConflictDoNothing` and then fetch. Since the partial unique index only
  covers `isDefault = true`, the insert will fail silently if the default already exists.
  Alternative cleaner approach: single `findFirst` — if null, do the seed insert, then
  return TestMap constant as the payload (avoids second DB round-trip).
- **Return type**: `{ id: number; name: string; mapData: MapData } | null`
  (null only if no default and seed fails, which should not occur in practice)

```ts
getDefaultMap: publicProcedure.query(async ({ ctx }) => {
  const existing = await ctx.db.query.maps.findFirst({
    where: eq(maps.isDefault, true),
  });
  if (existing) {
    return { id: existing.id, name: existing.name, mapData: existing.mapData };
  }
  // Table empty or no default — seed from built-in TestMap
  const [seeded] = await ctx.db
    .insert(maps)
    .values({
      name: TestMap.name,
      mapData: TestMap as unknown as Record<string, unknown>,
      isDefault: true,
      ownerUserId: null,
    })
    .onConflictDoNothing()
    .returning();
  if (!seeded) {
    // Race condition: another request seeded it first; fetch again
    const race = await ctx.db.query.maps.findFirst({
      where: eq(maps.isDefault, true),
    });
    return race ? { id: race.id, name: race.name, mapData: race.mapData } : null;
  }
  return { id: seeded.id, name: seeded.name, mapData: seeded.mapData };
}),
```

#### `list` — ADMIN-ONLY

- **Visibility**: `adminProcedure`
- **Behavior**: Return all maps ordered by id asc: `{ id, name, isDefault, createdAt }[]`
- No input.

#### `get` — ADMIN-ONLY

- **Visibility**: `adminProcedure`
- **Input**: `z.object({ id: z.number().int().positive() })`
- **Behavior**: Fetch by id; throw `NOT_FOUND` if absent.
- **Return**: Full row including `mapData`.

#### `save` (create or update) — ADMIN-ONLY

- **Visibility**: `adminProcedure`
- **Input**:
  ```ts
  z.object({
    id: z.number().int().positive().optional(), // absent = create; present = update
    name: z.string().min(1).max(256),
    mapData: mapDataSchema,                     // full schema validation on every save
  })
  ```
- **Behavior**:
  - If `id` absent: insert new row (non-default), set `ownerUserId = ctx.user.id`.
  - If `id` present: update `name`, `mapData`, `updatedAt` for the matching row.
    Do NOT change `isDefault` here (that's `setDefault`'s job).
  - Throw `NOT_FOUND` on update if id does not exist.
- **Validation**: `mapDataSchema` from `#14` is applied by Zod input parsing — no extra
  runtime call needed. tRPC Zod integration validates and throws `BAD_REQUEST` automatically.

#### `setDefault` — ADMIN-ONLY (ATOMIC BATCHED SWAP)

- **Visibility**: `adminProcedure`
- **Input**: `z.object({ id: z.number().int().positive() })`
- **The single-default invariant problem**: Must atomically (a) clear any existing default
  and (b) set the new one. Interactive transactions are unavailable (neon-http driver).
  **Solution**: `db.batch([...])` — confirmed available on `NeonHttpDatabase` at
  `node_modules/drizzle-orm/neon-http/driver.d.ts` line 27:
  `batch<U extends BatchItem<'pg'>, T extends Readonly<[U, ...U[]]>>(batch: T): Promise<BatchResponse<T>>`.
  The batch sends two statements in a single HTTP request; Neon executes them atomically
  within one implicit transaction.

```ts
setDefault: adminProcedure
  .input(z.object({ id: z.number().int().positive() }))
  .mutation(async ({ ctx, input }) => {
    // Verify the target map exists first (fast check; throw before touching DB state)
    const target = await ctx.db.query.maps.findFirst({
      where: eq(maps.id, input.id),
    });
    if (!target) throw new TRPCError({ code: "NOT_FOUND", message: "Map not found" });

    await ctx.db.batch([
      // Step 1: Clear current default (safe even if no row has isDefault=true)
      ctx.db.update(maps).set({ isDefault: false }).where(eq(maps.isDefault, true)),
      // Step 2: Set new default
      ctx.db.update(maps).set({ isDefault: true }).where(eq(maps.id, input.id)),
    ]);
  }),
```

**Note**: The partial unique index (`WHERE is_default = true`) enforces the invariant at the DB
level. The batched swap clears first, then sets — but within the same atomic batch so the index
constraint is never violated by a concurrent writer seeing two `true` rows simultaneously.

#### `delete` — ADMIN-ONLY

- **Visibility**: `adminProcedure`
- **Input**: `z.object({ id: z.number().int().positive() })`
- **Guards**:
  1. Fetch the row. If absent, throw `NOT_FOUND`.
  2. If `row.isDefault === true`, throw `FORBIDDEN` with message "Cannot delete the default map".
  3. Count total maps. If count === 1, throw `FORBIDDEN` with message "Cannot delete the only map".
  4. Otherwise, delete.

```ts
delete: adminProcedure
  .input(z.object({ id: z.number().int().positive() }))
  .mutation(async ({ ctx, input }) => {
    const row = await ctx.db.query.maps.findFirst({
      where: eq(maps.id, input.id),
    });
    if (!row) throw new TRPCError({ code: "NOT_FOUND" });
    if (row.isDefault)
      throw new TRPCError({ code: "FORBIDDEN", message: "Cannot delete the default map" });

    const [{ count }] = await ctx.db
      .select({ count: sql<number>`count(*)::int` })
      .from(maps);
    if (count <= 1)
      throw new TRPCError({ code: "FORBIDDEN", message: "Cannot delete the only map" });

    await ctx.db.delete(maps).where(eq(maps.id, input.id));
  }),
```

## 4. mapData Storage and Serialization

- Column type: `jsonb` (same as `gameSaves.saveData` and `debugOverrides.overrides` in schema.ts).

## 10. Risks & Unknowns

1. **`db.batch` semantics on Neon HTTP**: Confirmed available via
   `NeonHttpDatabase.batch<U, T>(batch: T): Promise<BatchResponse<T>>` (driver.d.ts line 27).
   Neon HTTP batch sends multiple statements as a single HTTP request executed atomically.
   Risk: if Neon's batch implementation does NOT guarantee transactional atomicity in all
   edge cases (e.g., statement-level vs. transaction-level), two concurrent `setDefault` calls
   could briefly violate the single-default invariant. The partial unique index is the true
   enforcement mechanism and will reject any second `isDefault = true` row at the DB level,
   causing one concurrent caller to receive a constraint violation error. This is acceptable
   behavior (fail-safe, not silent corruption).

2. **Partial unique index on boolean column**: A partial unique index on `is_default WHERE
   is_default = true` is a standard PostgreSQL pattern. However, Drizzle's `db:push` must
   correctly emit the `WHERE` clause. Verify post-push by inspecting `\d cat-herder_map` in
   psql. If the `WHERE` clause is dropped, fall back to an application-level check in
   `setDefault` (verify no other row has `isDefault = true` before setting the new one).

3. **`mapDataSchema` server import**: Confirmed clean — only imports `zod` and `~/game/types.ts`
   (pure enums/interfaces, no Three.js). No re-export needed. No risk.

4. **jsonb round-trip fidelity**: `MapData` contains nested arrays (`terrain: TerrainCell[][]`)
   and enums stored as strings. Postgres jsonb round-trips JSON faithfully. The Zod schema
   uses `z.nativeEnum` which accepts string values, so a re-parsed jsonb blob validates
   correctly. No risk.

5. **initialMap prop drilling**: The threading path crosses the `next/dynamic` boundary
   (GameLoader → GameCanvas). Props passed to a `dynamic` component still work normally in
   Next.js — the dynamic boundary only affects SSR exclusion, not prop passing. No risk.

6. **`api.map.getDefaultMap()` server-side**: The server-side tRPC caller (`~/trpc/server`)
   is already used in this project for similar patterns. Confirm the import path exists (check
   `src/trpc/server.ts`). If it doesn't, use `createCaller` directly from `src/server/api/root.ts`
   with a minimal context (no user needed — it's a publicProcedure).
