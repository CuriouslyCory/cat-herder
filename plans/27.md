## Goal

Extract the server-sync cluster (save / list / load / set-default / delete + the
`currentMapId` / `currentMapName` / `mapListCache` state and the client-side
delete guards) out of the 2,617-line `MapEditor` class into a dedicated
`MapPersistenceController`. The controller depends only on an injected tRPC
adapter (plus the pure `mapDataSchema` for load validation) and has **zero DOM /
Three.js coupling**, so every persistence flow becomes unit-testable with just a
fake adapter — no jsdom, no fake `SceneManager`, no fake camera.

This is a **behavior-preserving** extraction. `MapEditor` keeps its exact public
surface (`saveMapToDB`, `loadMapFromDB`, `refreshMapList`,
`setCurrentMapAsDefault`, `deleteCurrentMap`, `isDeleteDisabled`) and keeps all
DOM effects (error/status display, name-input sync, list `<select>` population,
button enable/disable, admin gating); it simply delegates the I/O and state
bookkeeping to the controller.

### Acceptance criteria

1. `MapEditor` contains **no tRPC call sites** and **no `currentMapId` /
   `currentMapName` / `mapListCache` bookkeeping**. Those live in
   `MapPersistenceController`; `MapEditor` reads them through getters.
2. `MapPersistenceController` is unit-tested with **only a fake tRPC adapter** —
   its test file imports no jsdom, no Three.js, no `SceneManager`/camera mocks,
   and does not construct a `MapEditor`.
3. The editor save / load / list / set-default / delete flows behave
   **identically**. All existing `MapEditor.test.ts` flow tests still pass,
   changed only where they reach into the moved state (the delegation seam).
4. The delete guards behave **exactly as before**: delete is blocked when no map
   is loaded (`currentMapId === null`), when the map list has ≤ 1 entry, or when
   the current map is the default. The user-facing guard message
   (`"Cannot delete the default map or the only map"`) is unchanged.
5. **No change to the external save-data shape.** `getMapData()` / `MapData` /
   `mapDataSchema` / the tRPC `map` router are untouched.
6. `pnpm build`, `pnpm lint`, `pnpm typecheck`, `pnpm test` all pass.

### Explicitly out of scope (belongs to #29)

#29 ("extract the DOM-free map-mutation core") is sequenced **after** #27 and
depends on it. Do **not** extract terrain/entity mutation (`placeBlock`,
`createWaterZone`, `placeEntity`, `getMapData`, `loadMapData`, the `terrain[][]`
logic) in this slice. #27 touches only the persistence cluster. `getMapData()`
and `loadMapData()` remain `MapEditor` methods; the controller receives/returns a
`MapData` value and never mutates terrain.

## Design

### New file: `src/game/maps/MapPersistenceController.ts`

Owns the tRPC I/O and the persistence state. DOM-free and Three.js-free. Imports
only `MapData` (type), `mapDataSchema` (pure zod), and defines the adapter type.

```ts
import type { MapData } from "./MapData";
import { mapDataSchema } from "./MapDataSchema";

/** One row from the map list (summary; no mapData blob). */
export interface MapListEntry {
  id: number;
  name: string;
  isDefault: boolean;
  createdAt: Date;
}

/**
 * Minimal DB surface the controller needs. Mirrors GameTrpcAdapter's map
 * methods (Game.ts) structurally so the concrete adapter satisfies it without
 * a circular import.
 */
export interface MapTrpcAdapter {
  mapList(): Promise<MapListEntry[]>;
  mapGet(input: { id: number }): Promise<{ id: number; name: string; mapData: unknown; isDefault: boolean }>;
  mapSave(input: { id?: number; name: string; mapData: MapData }): Promise<{ id: number; name: string }>;
  mapSetDefault(input: { id: number }): Promise<void>;
  mapDelete(input: { id: number }): Promise<void>;
}

/** Thrown by load() when the fetched mapData fails schema validation. */
export class MapValidationError extends Error {}

export class MapPersistenceController {
  private _currentMapId: number | null = null;
  private _currentMapName = "untitled";
  private _mapListCache: MapListEntry[] = [];

  constructor(private readonly adapter: MapTrpcAdapter | null = null) {}

  // ── reads (for MapEditor DOM) ──────────────────────────────────────────
  hasAdapter(): boolean { return this.adapter !== null; }
  getCurrentMapId(): number | null { return this._currentMapId; }
  getCurrentMapName(): string { return this._currentMapName; }
  getMapListCache(): readonly MapListEntry[] { return this._mapListCache; }

  // ── operations ─────────────────────────────────────────────────────────

  /** Create-or-update. Uses the tracked id (create when null). Updates state. */
  async save(input: { name: string; mapData: MapData }): Promise<{ id: number; name: string }> {
    if (!this.adapter) throw new Error("No DB adapter available");
    const result = await this.adapter.mapSave({
      id: this._currentMapId ?? undefined,
      name: input.name,
      mapData: input.mapData,
    });
    this._currentMapId = result.id;
    this._currentMapName = result.name;
    return result;
  }

  /** Fetch + validate a map. Does NOT touch state (caller applies, then markLoaded). */
  async load(id: number): Promise<{ id: number; name: string; mapData: MapData }> {
    if (!this.adapter) throw new Error("No DB adapter available");
    const row = await this.adapter.mapGet({ id });
    const result = mapDataSchema.safeParse(row.mapData);
    if (!result.success) {
      const msg = result.error.issues[0]?.message ?? "schema validation failed";
      throw new MapValidationError(`Invalid map data: ${msg}`);
    }
    return { id: row.id, name: row.name, mapData: result.data };
  }

  /** Record a successful load after the caller applied the data. */
  markLoaded(id: number, name: string): void {
    this._currentMapId = id;
    this._currentMapName = name;
  }

  /** Refresh + cache the map list. */
  async list(): Promise<MapListEntry[]> {
    if (!this.adapter) throw new Error("No DB adapter available");
    const list = await this.adapter.mapList();
    this._mapListCache = list;
    return list;
  }

  /** Set the tracked current map as default. */
  async setDefaultCurrent(): Promise<void> {
    if (!this.adapter) throw new Error("No DB adapter available");
    if (this._currentMapId === null) throw new Error("No map loaded");
    await this.adapter.mapSetDefault({ id: this._currentMapId });
  }

  /** Delete the tracked current map. Client guard mirrors the server guard. */
  async deleteCurrent(): Promise<void> {
    if (!this.adapter) throw new Error("No DB adapter available");
    if (this._currentMapId === null) throw new Error("No map loaded");
    if (this.isDeleteDisabled()) throw new Error("Cannot delete the default map or the only map");
    await this.adapter.mapDelete({ id: this._currentMapId });
    this._currentMapId = null;
  }

  /** True when delete must be blocked. Identical logic to the old MapEditor guard. */
  isDeleteDisabled(): boolean {
    if (this._currentMapId === null) return true;
    if (this._mapListCache.length <= 1) return true;
    const current = this._mapListCache.find((m) => m.id === this._currentMapId);
    if (current?.isDefault) return true;
    return false;
  }
}
```

**Why `load` returns instead of applying, plus `markLoaded`:** the original
`loadMapFromDB` (lines 645–657) fetches, validates, and only sets
`_currentMapId`/`_currentMapName` **after** `loadMapData()` runs and after a
validation failure has already `return`ed. Splitting into `load()` (fetch +
validate, no state change) and `markLoaded()` (state change, called after
`MapEditor.loadMapData()`) reproduces that exact ordering: on a validation
failure the state is never touched. `MapValidationError` lets `MapEditor`
distinguish the `"Invalid map data: …"` path from the generic `"Load failed"`
catch, preserving both messages.

**Why `deleteCurrent` also enforces the guard:** the guard is now unit-testable
at the controller level with just a fake adapter (AC #4). This is defense in
depth — `MapEditor` still pre-checks and shows the friendly message before
calling — so external behavior is unchanged (the throw path is never reached in
normal flow).

**Admin gating & name-input sync stay in `MapEditor`.** They are pure DOM
(`button.disabled`, `input.value`) and would re-introduce DOM coupling into the
controller, defeating AC #2. The controller owns the *state*
(`getCurrentMapName()`, `getCurrentMapId()`); `MapEditor` reads it to drive the
DOM. This is the intended split.

### How `MapEditor` consumes it

  (assigned in ctor, or `private _persistence!: ...` assigned before the prod

  guard at line 358 so it exists in production too).
- Remove fields `_currentMapId`, `_currentMapName`, `_mapListCache` (334–338)
  and the `MapTrpcAdapter` interface (45–51) — re-export the controller's
  `MapTrpcAdapter` from `MapEditor.ts` for any external importer, or import it.
- Rewrite the six methods as thin delegators that keep every DOM side effect and

The controller is created even when `trpcAdapter` is null (all its methods guard
on `hasAdapter()`), so the production early-return path and the "no adapter"
tests keep working.

## Test plan

### New: `src/game/__tests__/maps/MapPersistenceController.test.ts` (no jsdom)

Imports: `vitest`, `MapPersistenceController` + `MapValidationError` +
`MapListEntry`/`MapTrpcAdapter` from the controller, `MapData`/`TerrainType`
types. **No** `document`/`window` stubs, **no** `SceneManager`/camera mocks,
**no** `MapEditor` import. Provide a `makeFakeAdapter()` returning `vi.fn()`
methods and a `makeMapData()` helper (small valid grid). Suites:

1. **`save()`**
   - First save calls `mapSave` with `id: undefined` and the given name/mapData.
   - After a save that resolves `{ id: 42, name }`, `getCurrentMapId()` is 42 and
     the next save passes `id: 42`.
   - Rejects with `"No DB adapter available"` when constructed with `null`.
   - Propagates adapter rejection (network error) to the caller.

2. **`load()`**
   - Calls `mapGet({ id })`; returns `{ id, name, mapData }` with parsed data.
   - Throws `MapValidationError` (message starts `"Invalid map data:"`) when
     `mapGet` returns a `mapData` that fails `mapDataSchema` (e.g. `terrain: []`
     or a bad `spawnPoint.role`). Assert `err instanceof MapValidationError`.
   - `load()` does **not** mutate `getCurrentMapId()` (still null) on either
     success or validation failure — only `markLoaded()` does.
   - `markLoaded(id, name)` sets `getCurrentMapId()` / `getCurrentMapName()`.

3. **`list()`**
   - Calls `mapList` once, returns the entries, and caches them
     (`getMapListCache()` matches; drives `isDeleteDisabled()`).

4. **`setDefaultCurrent()`**
   - Throws `"No map loaded"` when `currentMapId` is null (no adapter call).
   - After `markLoaded(5, …)`, calls `mapSetDefault({ id: 5 })`.

5. **`deleteCurrent()` + delete guards (the AC #4 core)**
   - **Break-it discipline:** first write the guard assertions, then confirm they
     fail if the guard is removed (temporarily comment the `isDeleteDisabled`
     check in `deleteCurrent`), then restore.
   - No map loaded (`currentMapId` null) → rejects `"No map loaded"`, `mapDelete`
     not called.
   - Only one map in cache → after `list()` returns 1 entry and
     `markLoaded(thatId, …)`, `isDeleteDisabled()` is `true` and
     `deleteCurrent()` rejects `"Cannot delete the default map or the only map"`;
     `mapDelete` not called.
   - Current map is default → cache has ≥2 entries, current entry
     `isDefault: true` → `isDeleteDisabled()` true, `deleteCurrent()` rejects;
     `mapDelete` not called.
   - Deletable (≥2 entries, current non-default) → `deleteCurrent()` calls
     `mapDelete({ id })` and clears `getCurrentMapId()` to null.

6. **`isDeleteDisabled()` truth table** (pure, no adapter calls)
   - null id → true; ≤1 entry → true; current is default → true; ≥2 entries &
     non-default → false. Never throws.
